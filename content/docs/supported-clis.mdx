**career-ops runs on every major AI coding CLI — you are not locked into any single vendor.** Because career-ops ships prompt files that the CLI executes (it does not bundle its own model), you point it at whichever AI coding assistant you already use and it runs on top of that engine unchanged. When a better model ships, you switch CLIs and keep your pipeline, your data and your setup.

<Callout title="Use what you already have">
The best CLI for career-ops is the one you already pay for. If you already pay for Claude Code, career-ops needs no other setup. If you want to run for free, see [Set up a free AI engine](/docs/free-ai-engine).
</Callout>

## Which CLIs are supported?

career-ops works first-class with **Claude Code, Cursor, Codex, OpenCode, Pi, Antigravity CLI, Grok Build CLI, Qwen, Kimi, Hermes Agent, and GitHub Copilot CLI** — eleven actively-maintained AI coding CLIs. (Gemini CLI remains only as a legacy wrapper, transitioned into Antigravity CLI.) The career-ops architecture is shared across CLIs: a single canonical `AGENTS.md` drives the logic, and thin per-CLI entry files handle the invocation nuances of each tool.

The **canonical, always-current list — with the exact command to invoke career-ops in each CLI — lives in the core repo** so it never drifts out of date:

- [docs/SUPPORTED_CLIS.md](https://github.com/career-ops-hq/career-ops/blob/main/docs/SUPPORTED_CLIS.md) — the full matrix of supported CLIs, entry files, and how to invoke them (interactive and headless/batch).

## Which CLIs can run a batch?

The [batch runner](/docs/introduction/guides/batch-evaluate-offers) (`batch/batch-runner.sh`) starts its own headless workers, and its `--cli` flag accepts a shorter list than the one above:

| `--cli` value | Worker command | How the batch runs |
|---------------|----------------|--------------------|
| `claude` (default) | `claude -p` | Three offers at a time by default (`--parallel`); rate-limited offers are retried within the same run |
| `opencode` | `opencode run`, or `ollama launch opencode` when `opencode` is not installed | One offer at a time, one attempt per offer in each run |
| `gemini` | `gemini -p` | One offer at a time, one attempt per offer in each run |
| `qwen` | `qwen -p` | One offer at a time, one attempt per offer in each run |

With every value, a failed offer is retried on a later run, up to `--max-retries`.

Being accepted by the runner is not the same as being supported. The runner still accepts `gemini`, but Gemini CLI is a legacy wrapper that has moved to Antigravity CLI, so it is not on the list of supported CLIs. The reverse also holds: Cursor, Codex, Pi, Antigravity CLI, Grok Build CLI, Kimi, Hermes Agent and GitHub Copilot CLI are supported, but the batch runner does not launch them as workers.

## Pi

Pi needs no wrapper file. It reads `AGENTS.md` from the career-ops folder and finds the shared skill on its own, so you start `pi` in that folder and call career-ops with `/skill:career-ops`, followed by the mode you want. For a single unattended run, use `pi -p "your prompt"`.

Some Pi builds ask you to trust a project before they load its skills. If `/skill:career-ops` is not available, run `/trust` once in the folder and then restart `pi`: the trust decision only applies to Pi sessions started afterwards. To install Pi, follow [Pi's own instructions](https://github.com/earendil-works/pi).

## Which one should I choose?

- **If you already pay for Claude Code, Codex, or Copilot, use that CLI.** career-ops runs on top with zero extra setup — open the CLI inside the career-ops folder.
- **To run career-ops at $0,** use [OpenCode with a free provider, a local model via Ollama, or the built-in OpenRouter runner](/docs/free-ai-engine).
- **If you need a specific model or provider,** point any of these CLIs at any OpenAI-compatible endpoint or local model: career-ops is model-agnostic, and nothing in career-ops changes.

Whichever CLI you pick, the career-ops [14 modes](/docs/reference/modes) behave the same way — the CLI is the engine, career-ops is the structure on top.
