**career-ops funziona su tutte le principali CLI AI per la programmazione: non sei legato a nessun fornitore.** Poiché career-ops distribuisce file di prompt che la CLI esegue (non include un proprio modello), lo punti sull'assistente AI per la programmazione che usi già e gira sopra quel motore senza modifiche. Quando esce un modello migliore, cambi CLI e ti tieni la tua pipeline, i tuoi dati e la tua configurazione.

<Callout title="Usa quello che hai già">
La CLI migliore per career-ops è quella che paghi già. Se paghi già Claude Code, career-ops non richiede nessun'altra configurazione. Se vuoi usarlo gratis, leggi [Configura un motore AI gratuito](/it/docs/free-ai-engine).
</Callout>

## Quali CLI sono supportate?

career-ops funziona con supporto completo su **Claude Code, Cursor, Codex, OpenCode, Pi, Antigravity CLI, Grok Build CLI, Qwen, Kimi, Hermes Agent e GitHub Copilot CLI**: undici CLI AI per la programmazione mantenute attivamente. (Gemini CLI resta solo come wrapper legacy, confluito in Antigravity CLI.) L'architettura di career-ops è condivisa tra le CLI: un unico `AGENTS.md` canonico guida la logica, e file di ingresso leggeri, uno per CLI, gestiscono le particolarità di invocazione di ogni strumento.

L'**elenco canonico e sempre aggiornato, con il comando esatto per invocare career-ops in ogni CLI, si trova nel repository principale**, così non rischia mai di diventare obsoleto:

- [docs/SUPPORTED_CLIS.md](https://github.com/career-ops-hq/career-ops/blob/main/docs/SUPPORTED_CLIS.md): la matrice completa delle CLI supportate, dei file di ingresso e di come invocarle (in modalità interattiva e headless/batch).

## Quali CLI possono eseguire un batch? [#which-clis-can-run-a-batch]

Il [runner batch](/it/docs/introduction/guides/batch-evaluate-offers) (`batch/batch-runner.sh`) avvia i propri worker headless, e la sua opzione `--cli` accetta un elenco più corto di quello qui sopra:

| Valore di `--cli` | Comando del worker | Come viene eseguito il batch |
|---|---|---|
| `claude` (predefinito) | `claude -p` | Tre annunci alla volta per impostazione predefinita (`--parallel`); gli annunci bloccati da un limite di frequenza vengono riprovati nella stessa esecuzione |
| `opencode` | `opencode run`, oppure `ollama launch opencode` se `opencode` non è installato | Un annuncio alla volta, un tentativo per annuncio a ogni esecuzione |
| `gemini` | `gemini -p` | Un annuncio alla volta, un tentativo per annuncio a ogni esecuzione |
| `qwen` | `qwen -p` | Un annuncio alla volta, un tentativo per annuncio a ogni esecuzione |
| `grok` | `grok -p` con `--always-approve` | Un annuncio alla volta, un tentativo per annuncio a ogni esecuzione |

Con qualsiasi valore, un annuncio fallito viene riprovato in un'esecuzione successiva, fino a `--max-retries`.

Essere accettata dal runner non significa avere supporto completo. Il runner accetta ancora `gemini`, ma Gemini CLI resta solo come wrapper legacy, confluito in Antigravity CLI. Vale anche il contrario: Cursor, Codex, Pi, Antigravity CLI, Kimi, Hermes Agent e GitHub Copilot CLI hanno supporto completo, ma il runner batch non le avvia come worker.

## Pi

Pi non ha bisogno di un file wrapper. Legge `AGENTS.md` dalla cartella di career-ops e trova da solo la skill condivisa: ti basta avviare `pi` in quella cartella e richiamare career-ops con `/skill:career-ops`, seguito dalla modalità che vuoi. Per una singola esecuzione non presidiata, usa `pi -p "your prompt"`.

Alcune versioni di Pi ti chiedono di autorizzare un progetto prima di caricarne le skill. Se `/skill:career-ops` non è disponibile, esegui `/trust` una volta nella cartella e poi riavvia `pi`: l'autorizzazione vale solo per le sessioni di Pi avviate dopo. Per installare Pi, segui le [istruzioni ufficiali di Pi](https://github.com/earendil-works/pi).

## Quale CLI scegliere?

- **Se paghi già Claude Code, Codex o Copilot, usa quella CLI.** career-ops ci gira sopra senza nessuna configurazione aggiuntiva: apri la CLI dentro la cartella di career-ops.
- **Per usare career-ops a 0 $,** usa [OpenCode con un provider gratuito, un modello locale tramite Ollama o il runner OpenRouter integrato](/it/docs/free-ai-engine).
- **Se ti serve un modello o un provider specifico,** punta una qualsiasi di queste CLI su un endpoint compatibile con OpenAI o su un modello locale: career-ops è indipendente dal modello e al suo interno non cambia nulla.

Qualunque CLI tu scelga, le [14 modalità](/it/docs/reference/modes) di career-ops si comportano allo stesso modo: la CLI è il motore, career-ops è la struttura che ci sta sopra.
