## Install the Playwright package

Run `npm install` from the career-ops root folder:

```bash title="Terminal"
npm install
```

This installs Playwright and all other project dependencies declared in `package.json`. Skip this step if you already ran it during initial setup.

## Download Chromium

Playwright needs its own copy of Chromium to automate. The installer normally downloads it automatically right after dependencies; if `npm run doctor` reports it missing, download it by running:

```bash title="Terminal"
npx playwright install chromium
```

This is a one-time step. You do not need to repeat it after `npm` updates.

## Configure the Playwright MCP

The Playwright MCP lets Claude control the browser directly during the `/career-ops apply` step — navigating to job application forms, reading field labels, and suggesting answers.

### Register the MCP server

Run this command from the career-ops root folder to register the Playwright MCP with Claude Code:

```bash title="Terminal"
claude mcp add --scope project playwright -- npx @playwright/mcp@latest
```

This is the one-step registration method from the [Playwright MCP docs](https://playwright.dev/docs/getting-started-mcp), with `--scope project` added so Claude Code writes the server entry to `.mcp.json` in the career-ops root, one of the files `npm run doctor` checks. The next time you start Claude Code there, approve the server when it asks.

To use it in every project instead, run the command with `--scope user`. `npm run doctor` does not read user-scoped servers, so it will then warn that it cannot detect the MCP even though Claude Code loads it.

### Manual configuration (alternative)

If you prefer to configure it by hand, add the following entry to `.mcp.json` in the career-ops root (create the file if it does not exist):

```json title=".mcp.json"
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}
```

Restart Claude Code after saving the file and approve the server when it asks. career-ops will then have access to `browser_navigate` and `browser_snapshot` during apply sessions.

## Verify the setup

Run the doctor script to confirm all three components are in place:

```bash title="Terminal"
npm run doctor
```

Look for confirmation that Playwright, Chromium, and the MCP server are all ready. If the check passes, setup is complete.

## Watch the browser fill out the form

The Playwright MCP opens a visible browser window by default (the setup above does not pass `--headless`), so you can see each page it reads and each field it fills.

To have it open the application in that window and fill out the entire form, add an instruction to the apply command:

<Tabs items={["Claude Code", "Codex", "OpenCode", "Qwen CLI"]}>
  <Tab value="Claude Code">
    ```bash
    /career-ops apply {company_name} open up with playwright the browser and fill out the entire form
    ```
  </Tab>
  <Tab value="Codex">
    ```bash
    Run the /career-ops apply command with the {company_name} argument. Then, use the Playwright MCP to open a browser window and fill out the entire form live.
    ```
  </Tab>
  <Tab value="OpenCode">
    ```bash
    Run the /career-ops apply command with the {company_name} argument. Then, use the Playwright MCP to open a browser window and fill out the entire form live.
    ```
  </Tab>
  <Tab value="Qwen CLI">
    ```bash
    Run the /career-ops apply command with the {company_name} argument. Then, use the Playwright MCP to open a browser window and fill out the entire form live.
    ```
  </Tab>

For Ashby, Playwright can inspect the form and help draft answers, but finish and submit in your ordinary system browser. Verify a success page or confirmation email before marking the application submitted.

Without that instruction, career-ops still uses Playwright and the MCP to read the form and draft your answers, in the same visible window.
