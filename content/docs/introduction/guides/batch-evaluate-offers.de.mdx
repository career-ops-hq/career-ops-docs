Nutze diese Anleitung, wenn du 10 oder mehr Stellenangebote prüfen willst und sie alle in einer Session abarbeiten möchtest statt eins nach dem anderen.

Jedes Angebot bekommt seinen eigenen Worker, eine headless Claude-Code-Session, sofern du nicht [ein anderes CLI wählst](#run-the-batch-on-another-cli). Dieser Worker liest deinen Lebenslauf, bewertet, wie gut du zur Stelle passt, schreibt einen vollständigen Bericht und speichert ein maßgeschneidertes PDF – ganz ohne dein Zutun.

## Schritt 1: Trag deine Angebote in die Eingabedatei ein

Das Batch-System liest Job-URLs aus einer Datei namens **`batch/batch-input.tsv`**. Stell sie dir als To-do-Liste für die Bewertung vor.

<div className="rounded-lg bg-radial-[at_bottom] from-blue-500/20 p-4 border bg-origin-border border-fd-primary/10 prose-no-margin dark:bg-black/20">
  <div className="rounded-xl bg-fd-background p-3">
    <Steps>
      <Step>
        Öffne **`batch/batch-input.tsv`** in einem beliebigen Texteditor.
      </Step>
      <Step>
        Füge pro Angebot eine Zeile hinzu. Jede Zeile hat vier Spalten, getrennt durch einen Tab:

        | Spalte | Was du einträgst |
        |--------|---------------|
        | `id` | Eine eindeutige Nummer für dieses Angebot (1, 2, 3, …) |
        | `url` | Die vollständige URL der Stellenanzeige |
        | `source` | Wo du sie gefunden hast (z. B. `LinkedIn`, `Greenhouse`) |
        | `notes` | Eine optionale Notiz – lass das Feld leer, wenn du keine hast |
      </Step>
      <Step>
        Speichere die Datei.
      </Step>
    </Steps>
  </div>
</div>

**Beispiel:**

```text title="batch-input.tsv"
id	url	source	notes
1	https://jobs.example.com/senior-engineer	LinkedIn	
2	https://greenhouse.io/jobs/fullstack-dev	Greenhouse	priority
3	https://builtinaustin.com/job/rails-dev	BuiltIn	
```

<Callout title="Tipp">
  Jede ID muss eine eindeutige Nummer sein. Überspringe keine Nummern und verwende keine doppelt.
</Callout>

## Schritt 2: Sieh dir deinen Batch vorab an (empfohlen)

Bevor du irgendetwas verarbeitest, mach einen kurzen Check, um zu sehen, wie viele Angebote warten. Noch wird nichts bewertet – das ist nur eine Vorschau.

```bash title="Terminal"
./batch/batch-runner.sh --dry-run
```

Du siehst eine Liste der ausstehenden Angebote mit ihren IDs. Wenn etwas nicht stimmt, korrigiere die Eingabedatei jetzt, bevor du Zeit mit einer fehlerhaften Liste verschwendest.

## Schritt 3: Starte den Batch

Wenn du so weit bist, starte den Batch. Mit Claude-Code-Workern, dem Standard, bewertet der Runner drei Angebote gleichzeitig; `--parallel` ändert diese Zahl.

**Drei gleichzeitig (der Standard; schneller, belastet deinen Rechner aber stärker):**

```bash title="Terminal"
./batch/batch-runner.sh
```

**Zwei gleichzeitig:**

```bash title="Terminal"
./batch/batch-runner.sh --parallel 2
```

**Eins nach dem anderen (am langsamsten, braucht am wenigsten Arbeitsspeicher):**

```bash title="Terminal"
./batch/batch-runner.sh --parallel 1
```

**Angebote unter einem Schwellenwert überspringen (z. B. unter 4,0 von 5):**

```bash title="Terminal"
./batch/batch-runner.sh --parallel 2 --min-score 4.0
```

Behalte das Terminal im Blick, während der Batch läuft. Jede Zeile zeigt dir, welches Angebot gerade verarbeitet wird und ob es fertig geworden oder fehlgeschlagen ist.

Stößt ein Claude-Worker an ein Rate-Limit, wartet der Runner und versucht dasselbe Angebot im selben Lauf erneut, höchstens `--rate-limit-sleep` Sekunden lang (Standard 300), und verarbeitet den Rest des Batches mit einem einzigen Worker. Jede dieser Wiederholungen im laufenden Lauf verbraucht einen der `--max-retries`-Versuche des Angebots. Ein Sitzungs- oder Nutzungslimit pausiert den Batch dagegen; setze ihn später mit `--resume-paused` fort.

### Den Batch mit einem anderen CLI ausführen [#run-the-batch-on-another-cli]

Der Runner nutzt Claude Code, solange du kein `--cli` angibst. Er akzeptiert vier Werte: `claude` (Standard), `opencode`, `gemini` und `qwen`. `--model` wählt das Modell für dieses CLI:

```bash title="Terminal"
./batch/batch-runner.sh --cli opencode --model qwen2.5:32b
```

Parallele Worker und Wiederholungen nach einem Rate-Limit im laufenden Lauf gibt es nur mit Claude. Mit jedem anderen `--cli` bewertet der Runner ein Angebot nach dem anderen (er setzt `--parallel` mit einer Warnung auf 1 zurück) und unternimmt pro Lauf nur einen Versuch je Angebot. Schlägt dieser Versuch fehl, wird das Angebot als fehlgeschlagen markiert und wartet auf einen späteren Lauf, der es wie in Schritt 5 beschrieben erneut versucht. Unter [Unterstützte KI-CLIs](/de/docs/supported-clis#which-clis-can-run-a-batch) siehst du, wie sich diese Liste von den CLIs unterscheidet, die career-ops unterstützt.

Findet ein delegierter Worker eine Anzeige einer Personalvermittlung, die deine Bestätigung braucht, hält er an, bevor er einen Bericht, einen Lebenslauf, einen Bewerbungsentwurf oder eine Tracker-Zeile schreibt, und markiert den Job als `needs_confirmation`. Beantworte die angezeigte Frage in der übergeordneten interaktiven Sitzung; erst nach deiner ausdrücklichen Antwort setzt diese Sitzung die angehaltene Anzeige fort. `--retry-failed` und `--resume-paused` setzen solche Bestätigungsstopps nicht fort.

## Schritt 4: Lies die Ergebnisse, sobald sie eintreffen

Du musst nicht warten, bis der Batch fertig ist. Die Ergebnisse erscheinen, sobald ein Angebot abgeschlossen ist.

**Vollständige Bewertungsberichte** → `reports/`

Jeder Bericht ist eine Datei mit einem Namen wie `042-company-name-2026-04-14.md`. Öffne sie, um Folgendes zu sehen:

- Eine Zusammenfassung der Stelle
- Wie gut dein Lebenslauf zur Stelle passt
- Eine Gehaltsrecherche
- Einen Vorschlag, wie du dich aufs Vorstellungsgespräch vorbereiten kannst

Jeder Bericht enthält außerdem eine **Risk Summary** (Risikoübersicht). Ihre Zeile **Fixed-term contract** (befristeter Vertrag) zitiert die ausdrückliche Befristung aus der Anzeige, meldet `✅ no fixed term disclosed`, wenn keine genannt wird, und ist als nicht bewertet markiert, wenn die Stellenbeschreibung nicht verfügbar war. Das zugehörige Feld der Machine Summary ist `risk_summary.fixed_term` mit genau einem dieser Werte:

| Wert | Bedeutung |
|------|-----------|
| `detected` | Die Anzeige beschreibt ausdrücklich eine befristete Stelle |
| `not_detected` | Es wurde keine ausdrückliche Befristung gefunden |
| `not_evaluated` | Die Stellenbeschreibung war für diese Prüfung nicht verfügbar |

**Tracker-Einträge** → `batch/tracker-additions/`

Jedes Angebot legt hier außerdem eine kurze Zusammenfassungsdatei ab: eine Kopfzeile mit den Spaltennamen und eine Zeile mit den Werten. Diese werden in Schritt 6 in deinen Haupt-Tracker übernommen.

### Score Evidence

Der Bericht enthält nach der Risk Summary den Abschnitt **Score Evidence**. Er deckt fünf Dimensionen ab: CV-Match, North-Star-Ausrichtung, Vergütung, kulturelle Signale und Red Flags. Jede Zeile hält einen Evidenzstatus fest (`supported`, `partial` oder `unknown`), eine konkrete Quelle oder Beobachtung und eine offene Frage. Der Abschnitt endet mit einer Stufe für das Vertrauen in die Evidenz (`High`, `Medium` oder `Low`), ihrer Begründung und bis zu drei Prüfprioritäten.

Diese Stufe beschreibt die Evidenz hinter dem Global Score. Sie ist weder eine Einstellungswahrscheinlichkeit noch die Legitimitätsstufe der Anzeige aus Block G, und sie ändert den numerischen Score nicht. Die Machine Summary führt die fünf Status in `score_evidence`, die Stufe in `confidence` und die Prioritäten in `confidence_gaps`. Bleiben keine Prioritäten übrig, ist `confidence_gaps` eine leere Liste.

## Schritt 5: Wiederhole fehlgeschlagene Angebote

Manchmal schlägt ein Worker fehl – zum Beispiel, wenn die URL einer Stellenanzeige nicht mehr lädt. Fehlgeschlagene Angebote erscheinen im Terminal mit einer kurzen Fehlermeldung.

Das sind Wiederholungen in späteren Läufen, und sie funktionieren mit jedem CLI gleich: Der nächste Lauf nimmt jedes fehlgeschlagene Angebot wieder auf, bis es seine `--max-retries`-Versuche aufgebraucht hat. Sie sind etwas anderes als die Wiederholungen nach einem Rate-Limit im laufenden Lauf aus Schritt 3, die nur Claude-Worker machen, auch wenn beide auf dasselbe `--max-retries`-Limit angerechnet werden. Ein einfaches `./batch/batch-runner.sh` wiederholt fehlgeschlagene Angebote zusammen mit den ausstehenden.

**Nur die fehlgeschlagenen Angebote wiederholen:**

```bash title="Terminal"
./batch/batch-runner.sh --retry-failed
```

**Mit bis zu 3 statt der standardmäßigen 2 Versuche wiederholen:**

```bash title="Terminal"
./batch/batch-runner.sh --retry-failed --max-retries 3
```

Der Batch überspringt jedes Angebot, das bereits erfolgreich abgeschlossen wurde – ein erneuter Durchlauf ist also immer unbedenklich.

## Schritt 6: Führe die Ergebnisse in deinem Tracker zusammen

Wenn der Batch fertig ist, führe diesen Befehl aus, um alle neuen Bewertungen zu `data/applications.md` hinzuzufügen:

```bash title="Terminal"
node merge-tracker.mjs
```

Dieses Script:

1. Liest die Zusammenfassungsdateien aus `batch/tracker-additions/`
2. Prüft auf Duplikate, damit du nie zwei Zeilen für dasselbe Angebot bekommst
3. Fügt neue Einträge zu deinem Bewerbungs-Tracker hinzu
4. Archiviert die verarbeiteten Dateien in `batch/tracker-additions/merged/`

**Um die Änderungen vorab anzusehen, ohne etwas zu schreiben:**

```bash title="Terminal"
node merge-tracker.mjs --dry-run
```

## Wie es weitergeht

Öffne **`data/applications.md`**, um alle deine Bewertungen in einer Tabelle zu sehen. Von dort aus kannst du:

- Nach Score sortieren, um die Stellen zu finden, die am besten zu dir passen
- Einzelne Berichte in `reports/` öffnen, um tiefer einzusteigen
- Mit `/career-ops apply` den Bewerbungsprozess für deine Favoriten starten
