Este guia leva você do zero à sua primeira vaga avaliada em cerca de quinze minutos na primeira vez. Você vai configurar o workspace, abrir o seu assistente de programação com IA e colar uma vaga. O agente conclui o onboarding que for necessário e, em seguida, entrega um relatório completo, uma nota e um currículo em PDF sob medida.

## O que você precisa

Você não precisa saber programar. Basta se sentir à vontade para abrir um terminal e executar um comando.

<Callout title="Nunca usou o terminal?">
  Se você nunca usou uma linha de comando, não tem problema nenhum — mas este guia não é o lugar para aprender isso. Para pegar o jeito rapidamente, leia o manual [Command Line for Beginners](https://www.freecodecamp.org/news/command-line-for-beginners/), do freeCodeCamp (em inglês). Ele cobre tudo o que você precisa para acompanhar este guia. Quando estiver à vontade para abrir um terminal e executar um comando, volte e continue a partir do Passo 1.
</Callout>

## Passo 1: Configure o workspace

Abra um terminal na pasta onde você quer que o career-ops fique. O caminho recomendado usa um único comando; logo abaixo há um caminho avançado com `git clone`. Se o Node (22.13+, ou 23.4+ no Node 23) ou o Git não estiverem instalados, o `npx` vai se recusar a rodar — instale os dois primeiro (veja os pré-requisitos acima).

### Recomendado — um único comando

```bash title="Terminal"
npx @santifer/career-ops init
```

Esse comando clona a versão mais recente em `./career-ops`, instala as dependências e monta a estrutura do workspace. Ele também detecta qual CLI de programação com IA você tem instalada e informa o comando certo para começar. Ele só instala em uma pasta nova: se `./career-ops` já existir e não estiver vazia, o comando para com um erro e não altera nada; portanto, executá-lo de novo não repara nem atualiza um workspace existente.

Quando terminar, entre no workspace:

```bash title="Terminal"
cd career-ops
```

<details>
<summary>Avançado — clone o repositório você mesmo</summary>

Use este caminho se você quiser acompanhar um branch específico, contribuir com o projeto ou auditar o código antes de instalar as dependências.

```bash title="Terminal"
git clone https://github.com/career-ops-hq/career-ops.git
cd career-ops
npm install
```

</details>

### Navegador headless (uma única vez)

O career-ops usa um Chromium headless para várias tarefas: renderizar PDFs, verificar se as vagas continuam abertas e executar varreduras completas em ATS. O instalador o configura automaticamente depois das dependências; se essa etapa falhou na sua máquina, instale manualmente:

```bash title="Terminal"
npx playwright install chromium
```

<Callout title="O onboarding começa quando o seu perfil é necessário">
  Antes da sua primeira avaliação de vaga ou de outro fluxo que precise do seu perfil, o agente do career-ops verifica a sua configuração e, se necessário, conduz uma breve conversa de onboarding. Você também pode pedir diretamente que ele faça o onboarding. Ele pede o seu currículo, os tipos de cargo que você busca, a sua faixa de remuneração e a sua preferência de localização. Você responde em linguagem natural e o agente escreve os arquivos de configuração para você. A sessão leva de dois a três minutos. Explorar o workspace, revisar código ou diagnosticar a sua configuração não inicia o onboarding nem cria arquivos de perfil.

<Callout title="Um aviso sem relação com o career-ops que pode aparecer">
  Algumas CLIs (o Claude Code, por exemplo) perguntam se você confia nos arquivos de uma pasta nova na primeira vez que você a abre. Esse aviso vem da própria CLI, não do career-ops. Responda que sim para continuar. Aceitá-lo não inicia o onboarding do career-ops.
</Callout>

<Callout type="warn" title="Você paga o Claude Pro ou Max? Confira o que esta sessão está cobrando">
  Execute `node doctor.mjs` na pasta `career-ops` antes da sua primeira avaliação. Ele informa a sua fonte de cobrança em uma linha.

  Se `ANTHROPIC_API_KEY` estiver definida no seu ambiente, **a sua CLI a utiliza e cobra por token, mesmo que você pague o Pro ou o Max.** Essa precedência é do Claude Code, não do career-ops: o doctor apenas a detecta e avisa você. Para usar a sua assinatura, remova a linha `export ANTHROPIC_API_KEY=...` de `~/.zshrc`, `~/.bashrc`, `~/.profile` ou de um `.env` do projeto, reinicie o terminal e execute `/login`. Se a sua intenção era usar créditos de API, não há nada de errado.

  Cada uma das outras CLIs define a sua própria regra de assinatura versus chave, que o career-ops não verifica. Veja a resposta completa nas [perguntas frequentes](/pt/docs/faq).
</Callout>

## Como ler os seus resultados

O relatório inclui a seção **Score Evidence** depois de Risk Summary. Ela cobre cinco dimensões: aderência do currículo, alinhamento com a North Star, remuneração, sinais culturais e sinais de alerta. Cada linha registra um status de evidência (`supported`, `partial` ou `unknown`), uma fonte ou observação concreta e uma pergunta em aberto. A seção termina com um nível de confiança da evidência (`High`, `Medium` ou `Low`), o motivo e até três prioridades de verificação.

Abra o arquivo do relatório em `reports/`. O nome do arquivo segue o padrão `{number}-{company}-{date}.md`. Dentro dele, você vai encontrar:

- **Nota** — um número de 1 a 5. Qualquer valor abaixo de 4,0 indica que a vaga provavelmente não é uma boa opção para você.
- **Bloco A** — um resumo do cargo em linguagem simples.
- **Bloco B** — uma tabela que mostra como o seu currículo atende a cada requisito da vaga, além das lacunas.
- **Bloco C** — uma recomendação de estratégia para você se posicionar para esse cargo.
- **Bloco D** — pesquisa de remuneração que compara o que a vaga paga com os valores de mercado.
- **Bloco E** — notas de personalização para a sua candidatura.
- **Bloco F** — preparação para entrevistas, com histórias no método STAR feitas sob medida para essa vaga.
- **Bloco G** — legitimidade da vaga: uma verificação heurística de sinais, como se a vaga continua aberta e se ela vem sendo republicada repetidamente. O bloco relata o que encontra e deixa o julgamento com você.
- **Bloco H** — rascunhos de respostas para o formulário de candidatura, escritos somente quando a nota é 4,5 ou superior.

O seu currículo em PDF sob medida está na pasta `output/`. Revise-o antes de enviá-lo para qualquer lugar — o career-ops nunca envia nada sem a sua aprovação.

## Próximos passos

Agora que a sua primeira avaliação está pronta, veja algumas coisas que você pode explorar:

- **Refine o seu perfil.** Conte ao agente algo novo sobre você — *"Aqui vai mais contexto: acabei de entregar X."* Ele atualiza o perfil e as próximas avaliações ficam mais precisas.
- **Avalie mais vagas.** Cole mais URLs ou descrições. Cada uma entra no seu tracker.
- **Faça uma varredura em páginas de vagas.** Digite `/career-ops scan` para buscar de uma só vez em dezenas de páginas de carreiras de empresas pré-configuradas.
- **Compare vagas.** Se você tiver vários relatórios, digite `/career-ops ofertas` para obter uma comparação ranqueada.

## Solução de problemas

<Accordions>
  <Accordion title="O agente não fez o onboarding">
    O onboarding automático começa quando você pede uma avaliação de vaga ou outro fluxo que precise do seu perfil, e somente se a configuração estiver incompleta. Para iniciá-lo diretamente, abra a sua CLI de dentro da pasta `career-ops` (execute `pwd` para conferir) e diga ao agente: *"por favor, execute o onboarding inicial."*
  </Accordion>
  <Accordion title="O relatório não foi gerado">
    Confira se o `cv.md` existe na pasta raiz e se tem conteúdo. Se o onboarding terminou, mas o `cv.md` está vazio, peça ao agente: *"meu cv.md parece estar vazio, você pode me ajudar a preenchê-lo?"*
  </Accordion>
  <Accordion title="O PDF não foi gerado">
    Execute `npx playwright install chromium` de novo. Se isso não resolver, confira se o Node.js está na versão 22.13 ou superior (23.4 ou superior no Node 23) executando `node --version`.
  </Accordion>
  <Accordion title="A nota parece errada">
    As primeiras avaliações são imprecisas — o sistema ainda não conhece você bem. Depois de cada avaliação, diga ao seu assistente de IA o que ele errou. Por exemplo: *"Essa nota está alta demais — não tenho experiência com Kubernetes."* Ele vai aprender e se ajustar.
  </Accordion>
  <Accordion title="Outra coisa não está funcionando">
    Pergunte diretamente ao seu assistente de IA: *"O que há de errado com a minha configuração?"* Se ele não conseguir diagnosticar, execute `npm run doctor` para uma verificação completa.
  </Accordion>
</Accordions>

## Encontrou um bug ou tem alguma dúvida?

Se algo não estiver funcionando como este guia diz que deveria, avise a gente. Os relatos de bugs ajudam todo mundo que vier depois de você.

- **Relate um bug:** Abra uma issue no [repositório do GitHub](https://github.com/career-ops-hq/career-ops/issues). Descreva o que você esperava que acontecesse, o que aconteceu de fato e cole qualquer mensagem de erro que tenha aparecido.
- **Tire uma dúvida:** Entre na [comunidade do Discord](https://discord.gg/8pRpHETxa4). É o jeito mais rápido de receber ajuda de outros usuários e do autor.
- **Contribua com uma correção:** Se você sabe corrigir o problema por conta própria, leia o [CONTRIBUTING.md](https://github.com/career-ops-hq/career-ops/blob/main/CONTRIBUTING.md) antes de abrir um pull request. Em resumo: abra uma issue primeiro para uma nova funcionalidade, um novo modo ou comando, ou uma mudança de arquitetura. Correções de bugs, novos provedores de scanner sem autenticação, documentação e traduções podem ir direto para um pull request.
