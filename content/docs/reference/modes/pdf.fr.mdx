## Ce qu'il fait

Le mode pdf lit votre cv.md maître ainsi que le contexte de la JD, puis exécute l'étape de personnalisation (réécriture des puces, réorganisation des sections, intégration des mots-clés prioritaires) avant l'export en PDF via Playwright, avec un modèle CSS qui respecte les conventions des parseurs ATS. Le résultat est prêt à être téléversé.

## Quand l'utiliser

Utilisez pdf lorsque vous avez déjà évalué l'annonce et décidé de postuler, et que vous souhaitez uniquement le PDF personnalisé sans relancer l'étape d'évaluation.

## À quoi ressemble une exécution

Vous pointez le mode vers une annonce déjà évaluée et il produit un seul PDF personnalisé, prêt pour les ATS — sans réévaluation. Il extrait 15 à 20 mots-clés de la JD, choisit le format de papier selon la localisation de l'entreprise, réécrit votre résumé et réorganise les puces autour du poste, puis convertit le HTML en PDF et indique la couverture des mots-clés.

```bash title="Terminal"
/career-ops pdf acme

# detected JD language: en · paper: letter (US) · 18 keywords extracted
node generate-pdf.mjs output/cv-jane-doe-acme.html \
  output/cv-jane-doe-acme-2026-05-18.pdf --format=letter --report=008

PDF:   output/cv-jane-doe-acme-2026-05-18.pdf
Pages: 2 · Keyword coverage: 16/18 (89%)
```

La mise en page reste sur une seule colonne, avec des en-têtes de section standard et du texte sélectionnable — la structure que les parseurs ATS lisent sans difficulté — et les mots-clés sont intégrés à de véritables réalisations, jamais inventés.

## Quand y recourir

Recourez à pdf lorsque vous avez décidé de postuler et que vous souhaitez uniquement le CV personnalisé, en sautant l'étape d'évaluation. Quelques comportements à connaître :

- Le format de papier suit automatiquement la localisation de l'entreprise : `letter` pour les postes aux États-Unis et au Canada, `a4` partout ailleurs.
- L'injection de mots-clés repose sur la vérité. Le mode reformule une expérience réelle dans le vocabulaire exact de la JD, mais n'ajoute jamais une compétence que vous ne possédez pas.
- Pour la région DACH et une grande partie de l'Europe continentale, vous pouvez opter pour une photo en renseignant `candidate.photo` dans `config/profile.yml` ; laissez ce champ vide et le CV s'affiche à l'identique, au pixel près, sans photo — le choix par défaut le plus sûr pour les États-Unis, le Royaume-Uni et les marchés centrés sur les ATS.

## Vérifier comment un ATS le lira

Le mode `ats` répond à une autre question que pdf : le parseur d'un logiciel de suivi des candidatures lira-t-il correctement ce CV ? Exécutez `/career-ops ats`. Il procède en deux étapes, car la lecture se joue à deux endroits.

| Étape | Script | Lit | Renvoie |
| ----- | ------ | --- | ------- |
| Avant la génération du HTML | `ats-payload.mjs` | Les données du CV personnalisé que pdf s'apprête à rendre | Les mêmes données avec une correction appliquée, plus des constats pour vous |
| Après la génération du HTML | `verify-ats.mjs` | Le HTML généré dans `output/` | Un score de 0 à 100, une note en lettre et une liste de problèmes |

### Avant le HTML : une correction, trois constats

La correction : vos compétences clés passent dans la section Skills sous la forme d'une seule ligne séparée par des virgules. Le CV mis en forme affiche ces compétences comme des étiquettes séparées seulement par un espacement, si bien qu'un parseur qui lit le texte les colle les unes aux autres. Elles figurent en outre sous « Core Competencies », un titre que les parseurs ne reconnaissent pas, et le bloc entier est donc souvent écarté. « Skills » est reconnu. Ce déplacement n'invente rien, et l'exécuter deux fois ne change rien.

Les trois constats sont signalés et jamais appliqués, ni par le script ni par l'agent :

- `employer-in-role` : le nom d'un employeur dans l'intitulé d'un poste, fréquent dans le conseil et en agence. Le parseur l'enregistre comme un employeur que vous n'avez jamais eu.
- `parenthetical-in-company` : une entreprise écrite `Globex (Cloud Platform Division)`. Le parseur conserve la parenthèse dans le nom de l'employeur, et une recherche sur l'employeur ne vous trouve donc pas.
- `multiple-date-ranges` : deux périodes dans une même entrée. Deux passages chez un même employeur sont lus comme un seul.

Chacun demande une décision qui vous appartient : ce texte est-il un employeur, où le détail doit-il aller, quelles puces relèvent de quel passage. L'agent vous montre le constat et vous laisse décider. Si vous choisissez une modification, elle est écrite dans `cv.md` ou dans `config/profile.yml` après votre confirmation.

### Après le HTML : le score

`verify-ats.mjs` vérifie la structure du HTML généré : du texte sélectionnable, des titres de section standard, un e-mail de contact dans le corps, une seule colonne sans tableaux de mise en page, aucun texte dans des images, des polices standard, un encodage UTF-8 déclaré et aucun texte masqué. Le contrôle est réussi à partir de 70, sans aucun problème critique. Pour noter un CV que vous avez déjà généré, lancez-le vous-même :

```bash title="Terminal"
node verify-ats.mjs output/cv-jane-doe-acme.html
node verify-ats.mjs output/cv-jane-doe-acme.html --keywords "python,kubernetes,rag"
```

`--keywords` ajoute une ligne de couverture des mots-clés et ne modifie jamais le score.

Un score sans défaut ne signifie pas que la première étape était inutile. Un CV de test présentant le problème des compétences a obtenu 97 sur 100, note A, sans aucun problème, et a obtenu exactement le même résultat après la correction. Le score lit la structure du document qu'il reçoit. Il ne peut pas voir que les données qui se trouvent derrière seront mal lues.

Les deux scripts sont indicatifs. Ils fonctionnent sans modèle d'IA et sans connexion réseau, ne modifient jamais `cv.md` ni votre profil, et ne bloquent jamais la génération du PDF. Aucun des deux ne s'exécute lors d'un simple `/career-ops pdf`.

## Pièges à connaître

Nécessite Playwright installé en local. Le script de build peut échouer sur des installations Linux minimales dépourvues de polices système. Exécutez `npm run doctor` pour diagnostiquer.

La génération du PDF s'arrête si les postes de votre expérience professionnelle ne vont pas du plus récent au plus ancien, et l'erreur cite les dates du poste qui commence après celui du dessus. Remettez les postes dans l'ordre antéchronologique et relancez : on adapte un CV par le résumé et les puces, pas en déplaçant les postes. Si vous voulez délibérément un autre ordre, passez `--allow-nonchronological` à `generate-pdf.mjs` : le PDF est généré avec un avertissement. Avec `--batch`, seul le CV dans le désordre échoue ; les autres sont générés normalement.
