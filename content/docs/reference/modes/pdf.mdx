## What it does

pdf mode reads your master cv.md, the JD context, and runs the tailor step (rewriting bullets, reordering sections, integrating priority keywords) before exporting to PDF via Playwright with a CSS template that respects ATS parser conventions. The result is upload-ready.

## When to use it

Use pdf when you have already evaluated the listing and decided to apply, and want only the tailored PDF without re-running the evaluation step.

## What a run looks like

You point the mode at a listing you've already evaluated and it produces one tailored, ATS-ready PDF — no re-evaluation. It extracts 15-20 keywords from the JD, picks the paper size from the company's location, rewrites your summary and reorders bullets around the role, then renders the HTML to PDF and reports keyword coverage.

```bash title="Terminal"
/career-ops pdf acme

# detected JD language: en · paper: letter (US) · 18 keywords extracted
node generate-pdf.mjs output/cv-jane-doe-acme.html \
  output/cv-jane-doe-acme-2026-05-18.pdf --format=letter --report=008

PDF:   output/cv-jane-doe-acme-2026-05-18.pdf
Pages: 2 · Keyword coverage: 16/18 (89%)
```

The layout stays single-column with standard section headers and selectable text — the structure ATS parsers read cleanly — and keywords are woven into real achievements, never invented.

Keyword coverage is measured against the keyword section of the listing's evaluation report. If the report has none, career-ops scores the skills it finds in the report's archived job description instead and tells you which source it used. A report without a keyword section is a defect to fix in the report, not a pass.

## When to reach for it

Reach for pdf when you've decided to apply and want only the tailored resume, skipping the evaluation step. A few behaviors worth knowing:

- Paper size follows the company's location automatically: `letter` for US and Canada roles, `a4` everywhere else.
- Keyword injection is truth-based. The mode rewords real experience into the JD's exact vocabulary but never adds a skill you do not have.
- For DACH and much of continental Europe you can opt into a photo by setting `candidate.photo` in `config/profile.yml`; leave it empty and the CV renders pixel-for-pixel identical without one, which is the safer default for US, UK, and ATS-first markets.

## Gotchas

Requires Playwright installed locally. The build script may fail on minimal Linux installs missing system fonts. Run `npm run doctor` to diagnose.

PDF generation stops when your Work Experience entries are not newest-first, and the error quotes the dates of the role that starts later than the one above it. Put the roles back in reverse-chronological order and rerun: tailor a CV through the summary and the bullets, not by moving roles. If you deliberately want another order, pass `--allow-nonchronological` to `generate-pdf.mjs` and it renders with a warning instead. With `--batch`, only the out-of-order CV fails and the rest still render.

`generate-pdf.mjs` records each PDF it writes in `data/pdf-index.tsv`, and career-ops reads that file to find the CV for a report. Each row carries a `kind` of `cv` or `cover`, and a report keeps one row of each. Regenerating a PDF replaces only the row of its own kind.

Without `--kind`, the kind comes from the output filename. A name that starts with `cv-` is a CV, and one that starts with `cover-` or ends in `-cover` is a cover letter. Any other name is filed as a CV.

The cover mode files its letters as `cover` whatever their name, so the filename rule matters only when you run `generate-pdf.mjs` yourself. A letter rendered to `acme-letter.pdf` with `--report=008` replaces report 008's CV row, and a lookup of that CV returns the letter. Pass `--kind=cover` when the filename does not say which it is:

```bash title="Terminal"
node generate-pdf.mjs output/acme-letter.html output/acme-letter.pdf \
  --report=008 --kind=cover
```

`--kind` takes `cv` or `cover`, and any other value, empty included, stops the run before anything renders. `--batch` rejects it; set `"kind"` on an entry in the batch file instead. `generate-pdf.mjs` owns `data/pdf-index.tsv`, and its header line says not to edit it by hand.
