## 它做什么

retro 模式会读取你在当前会话中发送的消息，根据你纠正或否决过的内容提出最多五条规则，每条都以你的原话为依据。脚本会检查每条提案，只有你接受的规则才会保存到 `modes/_custom.md` 或 `modes/_profile.md`。

## 什么时候用

如果你在某次会话中纠正过 career-ops，比如“别再用第三人称写我的个人简介”，就在会话结束时运行 retro。你在聊天中做出的纠正只在当前会话有效；在这里接受的规则，下次会话依然有效。它需要你在场批准：在无人值守的运行中，它会停下来，并请你在交互式会话中运行。

## 运行过程

```txt title="Terminal"
> /career-ops retro
```

1. **找出经验。** 经验是指下次会话仍应有效的纠正或否决。
2. **进行分类。** 关于你本人的事实（比如某个岗位、某项技能或某个指标）不算规则：retro 会明确告诉你，并指引你使用记录这类信息的模式。评分或目标职位方面的偏好写入你的个人资料，其他长期偏好写入你的自定义规则。
3. **引用原话。** 每条提案都附上你的原话作为依据，一字不改。
4. **检查提案。** `learn.mjs` 会验证提案并为其编号，retro 将输出原样展示给你。被拦下的提案就保持拦下状态，retro 不会为了让它通过而改写措辞。
5. **由你按编号选择。** 说明要接受或否决哪几条。你没有提到的编号保持未决定状态。
6. **报告改动。** 它会列出每个改动的文件和行。如果本次会话没有可总结的经验，它会直接说明并结束。

## 它不会碰什么

retro 不会编辑你的简历、`article-digest.md` 或 `config/profile.yml`。它会在 `data/learning/` 下写入两个工作文件，除此之外的内容都只由 `learn.mjs` 写入：你接受的规则、每个被改动文件的 `.bak` 副本，以及记录每项决定的 `data/learning/ledger.jsonl`。
