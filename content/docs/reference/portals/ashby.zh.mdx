## 功能说明

providers/ashby.mjs 中的 ashby 适配器会向 api.ashbyhq.com/posting-api/job-board/`{slug}` 发送 HTTP 请求，并解析返回的 JSON。slug 是该公司在 Ashby 上的招聘页面标识符（例如 ElevenLabs 对应 'elevenlabs'）。career-ops 会根据条目中的 `careers_url`（`https://jobs.ashbyhq.com/<slug>`）或显式指定的 `api:` 字段来选用这个适配器。

## 适用场景

如果你的目标是 AI 实验室、基础设施公司和新兴初创公司，就用 Ashby 扫描。templates/portals.example.yml 中预配置了 40 个 Ashby 招聘页面，ElevenLabs、Deepgram、Sierra、Decagon 和 n8n 都在其中。

## 示例

```yaml title="portals.yml"
- name: ElevenLabs
  careers_url: https://jobs.ashbyhq.com/elevenlabs
  enabled: true
```

下次扫描时就会抓取 ElevenLabs 当前在招的职位。

## 扫描器做什么

扫描器从 portals.yml 读取你已启用的 Ashby slug，逐个调用 Ashby 公开的招聘页面 API，再把新职位合并进你的 pipeline：不需要浏览器，不需要登录，抓取本身也不消耗任何 LLM token。运行一次 `node scan.mjs`，就能同时覆盖你的 Ashby、Greenhouse 和 Lever 招聘页面，然后按你配置的职位名称关键词过滤结果。

```bash title="Terminal"
node scan.mjs
```

```txt title="Output"
Portal Scan - 2026-07-06
Offers found: 41 total
Filtered by title: 6 relevant
Duplicates: 3 (already evaluated or in pipeline)
New added to pipeline.md: 3

  + ElevenLabs | Applied AI Engineer | ashby
  + Deepgram   | Inference Engineer  | ashby
```

## career-ops 如何对接 Ashby

career-ops 调用 Ashby 公开的职位发布 API `api.ashbyhq.com/posting-api/job-board/{slug}?includeCompensation=true`，直接从 JSON 响应中读取 `jobs` 列表。对每个职位，它会读取标题、作为申请链接的公开 `jobUrl`、工作地点（主地点加上所有次要地点，远程职位还会加上“Remote”）、纯文本描述、发布日期，以及招聘页面公布薪资时的年化薪资范围。由于这是结构化的 API 调用，而不是抓取网页，扫描既不需要浏览器，也不消耗模型 token。Ashby 的公开 API 响应较慢，每个招聘页面最快也要 10 秒左右，而且会对重复请求限流，因此 career-ops 对每个招聘页面最多等待 30 秒，并按退避策略重试。只有之后进入评估步骤、你决定某个职位值得细看时，才会消耗 token。重复运行扫描是安全的：每个 URL 都会与你的扫描历史、已评估的申请记录以及当前 pipeline 进行去重比对，所以你已经见过的职位绝不会被重复添加。

## 注意事项

Ashby 的招聘页面 API 会直接返回完整的 JD 文本，不需要再发后续请求。每个招聘页面大约需要 10 秒才能响应，因此扫描大量 Ashby 招聘页面时，耗时会比同等数量的 Greenhouse 或 Lever 招聘页面稍长一些。
