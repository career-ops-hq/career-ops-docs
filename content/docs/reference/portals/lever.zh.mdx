## 它能做什么

providers/lever.mjs 中的 lever provider 会向 api.lever.co/v0/postings/`{slug}` 发送 HTTP 请求，并解析返回的 JSON。slug 是该公司在 Lever 上的职位发布标识符（例如 Figma 对应 'figma'）。

## 什么时候使用

如果目标公司处于 C 轮到上市前阶段，而且还没有迁移到 Greenhouse 或 Ashby，就用 Lever 扫描。Figma、Brex 以及很多金融科技公司仍在使用 Lever。

## 示例

```
In your portals.yml: `- provider: lever\n  slug: figma\n  careers_url: https://jobs.lever.co/figma` — scan picks up active Figma roles.
```

## 扫描器做了什么

扫描器会从 portals.yml 读取你启用的 Lever slug，逐个调用 Lever 的公开职位发布 API，再把新出现且职位名称匹配的职位合并到你的 pipeline 中。整个过程不需要浏览器会话，抓取环节也不消耗任何 LLM token。同一次 `node scan.mjs` 运行还会覆盖你的 Greenhouse 和 Ashby 招聘板，然后用你配置的职位名称关键词过滤所有结果。

```bash title="Terminal"
node scan.mjs
```

```txt title="Output"
Portal Scan - 2026-07-06
Offers found: 33 total
Filtered by title: 5 relevant
Duplicates: 2 (already evaluated or in pipeline)
New added to pipeline.md: 3

  + Figma | AI Product Engineer | lever
  + Brex  | Applied AI Engineer | lever
```

## career-ops 如何与 Lever 通信

career-ops 请求 `api.lever.co/v0/postings/{slug}`（欧盟的招聘板则使用 `api.eu.lever.co` 主机），并读取返回的职位 JSON 数组。对每个职位，它把 `text` 字段作为职位名称，把 `hostedUrl` 作为链接；如果没有 `hostedUrl`，就改用 `applyUrl`。由于 Lever 在一次结构化响应中返回整个招聘板，每家公司的扫描只需一次公开的 HTTPS GET 请求，不会超出速率限制，也不消耗任何模型 token。只有之后你评估某个想要争取的职位时，才会开始消耗 token。重复运行扫描是安全的：每个 URL 都会与你的扫描历史、已评估的申请和当前的 pipeline 进行去重，所以你已经看过的职位绝不会被重复添加。

## 注意事项

Lever 的 API 会在职位发布响应中提供完整的职位描述（JD）。有些 Lever 招聘板还包含职位的内部元数据，career-ops 会在评分时把它们作为额外的参考信号呈现出来。
