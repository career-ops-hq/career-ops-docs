## 功能简介

providers/greenhouse.mjs 中的 greenhouse provider 会向 boards-api.greenhouse.io/v1/boards/`{slug}`/jobs 发送 HTTP 请求，并把返回的 JSON 解析成 career-ops 的职位格式。slug 是公司在 Greenhouse 上的招聘页面标识符（例如 Anthropic 对应 'anthropic'）。

## 适用场景

如果你的目标公司用 Greenhouse 作为 ATS，就用 Greenhouse 扫描。员工规模在 50–10,000 人之间的美国科技公司大多都用它。templates/portals.example.yml 自带预先配置好的 Greenhouse 招聘页面，你可以直接启用。

## 示例

```yaml title="portals.yml"
- name: Anthropic
  careers_url: https://job-boards.greenhouse.io/anthropic
  enabled: true
```

下次扫描时，就会抓取 Anthropic 所有开放的职位。

## 扫描器做了什么

扫描器从 portals.yml 中读取你已启用的 Greenhouse slug，逐个调用公开的 boards API，再把标题匹配的新职位加入你的 pipeline。整个过程不抓取网页，获取数据时也不消耗任何 LLM token。运行一次 `node scan.mjs`，就能一并处理你的 Greenhouse、Ashby 和 Lever 招聘页面，然后按你配置的职位名称关键词筛选结果。

```bash title="Terminal"
node scan.mjs
```

## career-ops 如何对接 Greenhouse

career-ops 请求 `boards-api.greenhouse.io/v1/boards/{slug}/jobs?content=true`，从 JSON 中读取 `jobs` 数组，取出每个职位的标题、`absolute_url`、地点和完整的职位描述。完整描述就在同一个响应里返回，所以不需要为每个职位单独发请求。如果某个招聘页面只用工作模式（例如 Remote）来标注职位地点，career-ops 会再向该招聘页面的办公地点列表发一次请求，补上办公室名称。扫描本身只是对公开端点发起一次普通的 HTTPS GET 请求，所以不会超出速率限制，也不消耗任何模型 token。重复运行扫描是安全的：每个 URL 都会与你的扫描历史、已评估的申请以及当前的 pipeline 进行去重，你已经看过的职位绝不会被重复添加。

## 注意事项

由于每个职位都附带完整描述，在 Greenhouse 招聘页面上，`portals.yml` 中的内容过滤器（`content_filter`、`visa_filter` 和国家资格限制）会读取完整的职位文本，而不只是标题。职位很多的招聘页面只会返回一个大响应，而不是许多小响应。
