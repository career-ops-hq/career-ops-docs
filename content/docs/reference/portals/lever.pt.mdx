## O que faz

O provider lever, em providers/lever.mjs, faz requisições HTTP para api.lever.co/v0/postings/`{slug}` e interpreta a resposta em JSON. O slug é o identificador das vagas da empresa no Lever (por exemplo, 'mistral' para a Mistral AI).

## Quando usar

Use a varredura do Lever quando as empresas que você tem como alvo publicam suas vagas no Lever. A Mistral AI, a Palantir e o Spotify estão entre os painéis do Lever pré-configurados em templates/portals.example.yml.

## Exemplo

```yaml title="portals.yml"
- name: Mistral AI
  careers_url: https://jobs.lever.co/mistral
  enabled: true
```

A próxima varredura passa a captar as vagas ativas da Mistral AI.

## O que o scanner faz

O scanner lê os slugs do Lever habilitados no seu portals.yml, chama a API pública de vagas do Lever para cada um deles e incorpora ao seu pipeline as vagas novas cujo título corresponde ao que você procura, sem sessão de navegador e sem gastar nenhum token de LLM na coleta. A mesma execução de `node scan.mjs` também cobre seus painéis do Greenhouse e do Ashby e depois filtra tudo pelas palavras-chave de título que você configurou.

```bash title="Terminal"
node scan.mjs
```

## Como o career-ops se comunica com o Lever

O career-ops consulta `api.lever.co/v0/postings/{slug}`, ou o host `api.eu.lever.co` no caso de painéis da UE, e lê o array JSON de vagas. Para cada vaga, ele usa o campo `text` como título, o `hostedUrl` como link, a localização, a data de criação e a descrição completa. Como o Lever devolve o painel inteiro em uma única resposta estruturada, a varredura é um único GET HTTPS público por empresa, que fica dentro dos limites de requisições e não gasta tokens de modelo. O custo em tokens só começa depois, quando você avalia uma vaga que quer levar adiante. Rodar a varredura de novo é seguro: cada URL é comparada com o seu histórico de varreduras, com as candidaturas que você já avaliou e com o pipeline atual, de modo que uma vaga que você já viu nunca é adicionada duas vezes.

## Pontos de atenção

A API do Lever expõe a descrição completa da vaga na resposta: a introdução, cada seção de lista (como requisitos e responsabilidades) e o texto de encerramento. Os filtros de conteúdo do `portals.yml` (`content_filter` e `visa_filter`) leem tudo isso, de modo que uma expressão que aparece apenas na lista de requisitos de uma vaga do Lever continua sendo encontrada.
