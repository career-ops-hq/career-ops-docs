This guide walks through setting up `portals.yml` and running the portal scanner to find new job openings automatically.
<Callout title="Before you start">
  Make sure you have completed the [Quick Start](/docs) guide. You need `cv.md` and `modes/_profile.md` in place before scanning is useful.
</Callout>
## Set up portals.yml
`portals.yml` is the file that controls what the scanner looks for and where it looks. You create it once from the included template, then edit it to match your target roles.
Run this command from the project folder:
```bash title="Terminal"
cp templates/portals.example.yml portals.yml
```
Open `portals.yml` in any text editor. The file has three sections. The steps below walk through each one.
### Configure your title filter
The title filter is how the scanner decides if a job is worth showing you. It checks the job title against two lists of keywords.
Find the `title_filter` section near the top of the file:
```yaml title="portals.yml"
title_filter:
  positive:
    - "AI"
    - "ML"
    - "Product Manager"
  negative:
    - "Junior"
    - "Intern"
  seniority_boost:
    - "Senior"
    - "Staff"
    - "Lead"
```
**Replace the `positive` list** with keywords that match your target roles. A job must match at least one keyword from this list to pass through. The check is not case-sensitive, so `"AI"` also catches `"ai engineer"`.
**Replace the `negative` list** with keywords that rule a job out. If any of these appear in the title, the job is skipped — even if it matched a positive keyword.
**Leave `seniority_boost` as is** unless you want to add or remove seniority levels. These keywords do not filter anything out — they just move matching jobs higher in the results.
**Example:** If you are looking for Rails engineering roles, your filter might look like this:
```yaml title="portals.yml"
title_filter:
  positive:
    - "Rails"
    - "Ruby"
    - "Full Stack"
    - "Backend"
  negative:
    - "Junior"
    - "Intern"
    - "PHP"
    - "Java"
  seniority_boost:
    - "Senior"
    - "Staff"
    - "Lead"
```
<Callout title="Tip">
  Start with a small `positive` list of three to five keywords. You can always add more later. A long list makes it harder to see why a job passed or failed.
</Callout>
### Add companies to track
The `tracked_companies` section is a list of specific companies you want the scanner to check every time. The scanner goes directly to each company's job page and reads the open roles.
Find the `tracked_companies` section near the bottom of the file. Each entry looks like this:
```yaml title="portals.yml"
tracked_companies:
  - name: Anthropic
    careers_url: https://job-boards.greenhouse.io/anthropic
    api: https://boards-api.greenhouse.io/v1/boards/anthropic/jobs
    enabled: true
  - name: OpenAI
    careers_url: https://openai.com/careers
    enabled: true
```
**To add a company**, copy an existing entry and change the values:
<div className="rounded-lg bg-radial-[at_bottom] from-blue-500/20 p-4 border bg-origin-border border-fd-primary/10 prose-no-margin dark:bg-black/20">
  <div className="rounded-xl bg-fd-background p-3">
    | Field         | What to put                                                                                        |
    | ------------- | -------------------------------------------------------------------------------------------------- |
    | `name`        | The company name as you want it to appear in results                                               |
    | `careers_url` | The direct URL to the company's job listings page                                                  |
    | `api`         | Optional. The Greenhouse API URL if the company uses Greenhouse. Leave it out if you are not sure. |
    | `enabled`     | Set to `true` to include the company or `false` to skip it without deleting the entry.             |
  </div>
</div>
**To find a company's `careers_url`**, go to the company's website, click Careers or Jobs, and copy the URL of the page that lists open roles. That is the URL to use.
**To disable a company without deleting it**, set `enabled: false`:
```yaml title="portals.yml"
  - name: Stripe
    careers_url: https://stripe.com/jobs/search
    enabled: false
```
<Callout title="Note">
  Every company in `tracked_companies` must have a `careers_url`. Without it, the scanner has no page to visit and will skip that entry.
</Callout>
### Review the search queries
The `search_queries` section runs broader web searches to find roles at companies not in your tracked list. The template includes many pre-built queries.
You do not need to change this section to get started. The pre-built queries cover major job boards including Greenhouse, Ashby, among others.
When you are ready to customize, each query looks like this:
```yaml title="portals.yml"
search_queries:
  - name: Greenhouse — Rails Engineer
    query: 'site:job-boards.greenhouse.io "Rails Engineer" OR "Ruby on Rails" remote'
    enabled: true
```
To turn off a query you do not need, set `enabled: false`. To add a new one, copy an existing entry, give it a new `name`, and update the `query` text.
## Run a scan
There are two ways to run a scan. Use the one that fits what you need.
### Option A — Run the script directly
```bash title="Terminal"
npm run scan
```
Run this from the project folder. The script reads `portals.yml`, hits each company's API directly, and writes any new jobs to `data/pipeline.md`. It uses no AI tokens and runs in about 30 seconds.
This option works for any company whose job page runs on a platform the scanner has a built-in provider for: Greenhouse, Ashby, and Lever, plus dozens of other applicant tracking systems and job boards such as Workable, Workday, and SmartRecruiters. The full list is in [SUPPORTED_JOB_BOARDS.md](https://github.com/career-ops-hq/career-ops/blob/main/docs/SUPPORTED_JOB_BOARDS.md). Companies with no matching provider are skipped, and the scan reports how many.
**Preview results before saving them:**
```bash title="Terminal"
npm run scan -- --dry-run
```
This runs the full scan but does not write anything to disk. Use it to check your filter settings before committing results.
**Scan a single company:**
```bash title="Terminal"
npm run scan -- --company Anthropic
```
Replace `Anthropic` with any company name from your `tracked_companies` list. The match is not case-sensitive.
### Option B — Run the AI-powered scan inside Claude Code
Open Claude Code in the project folder and type:
```bash title="Claude Code"
/career-ops scan
```
This version visits each company's job page directly using a browser, so it works even for companies that do not have a public API. It also runs the `search_queries` from your `portals.yml` to find roles at companies not in your tracked list.
Use this option when:
- A company in your list uses a platform the script has no provider for, so the script scan skips it
- You want to discover new companies, not just check known ones
- The script scan missed something you expected to see
<Callout title="Tip">
  Option B uses Claude API tokens and takes longer than the script. For a quick daily check, Option A is faster.
</Callout>

  <div className="rounded-xl bg-fd-background p-3">

    |---|---|
    | **Companies scanned** | How many companies from `tracked_companies` were checked |
    | **Total jobs found** | All open roles seen across those companies, before any filtering |
    | **Filtered by title** | Jobs removed because the title did not match your `title_filter` |

If **New offers added** is 0, first look for this warning in the scan output:
```text title="Terminal"
⚠️  1 target(s) returned zero jobs without a successful HTTP response: Acme
```
It means that company's portal never answered successfully, so the zero does not prove its board is empty. The company is recorded as `unverified_zero` in `data/portal-health.tsv` and counts toward its failure streak. Check that portal before you change your filters.
If there is no such warning, your title filter may be too strict. Try adding a keyword to your `positive` list and run the scan again.
**Where new jobs go:** Each new offer is added as a line in `data/pipeline.md`. That is the list of jobs waiting to be evaluated.
**What `data/scan-history.tsv` does:** Every URL the scanner sees — whether it was added, filtered, or skipped — gets logged here. This is how the scanner avoids showing you the same job twice across future scans. One exception is a posting removed by your `location_filter` or `max_posting_age_days` setting in `portals.yml`. It is logged as `skipped_location` or `skipped_age`, and it can show up again once you change that setting. You do not need to edit this file.
## Evaluate new offers from a scan
After a scan adds new offers to `data/pipeline.md` — your list of pending job offers — run the pipeline command to evaluate each one against your profile. This step uses Claude to read the job description, compare it against your `cv.md` and `modes/_profile.md`, and produce a scored summary for each role.
Open Claude Code in the project folder and type:
```bash title="Terminal"
/career-ops pipeline
```

## What to do next
When `/career-ops pipeline` finishes, each job has a score from 1 to 5. You can find the full report for any role in the `reports/` folder. The score shows how well the role matches your profile.
Use the score as your starting point:
<div className="rounded-lg bg-radial-[at_bottom] from-blue-500/20 p-4 border bg-origin-border border-fd-primary/10 prose-no-margin dark:bg-black/20">
  <div className="rounded-xl bg-fd-background p-3">
    | Score             | Recommended action                                                                                                                    |
    | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
    | **4.5 or higher** | Strong match. Run `/career-ops apply` right away.                                                                                     |
    | **4.0 – 4.4**     | Good fit. Run `/career-ops apply`. You can also run `/career-ops contacto` first to reach out to someone on the team before applying. |
    | **3.5 – 3.9**     | Could go either way. Run `/career-ops deep` to learn more before you decide.                                                          |
    | **Below 3.5**     | Skip it unless you have a specific reason to apply.                                                                                   |
  </div>
</div>
Here is what each command does:
- **`/career-ops apply`** — Opens the application form and writes answers tailored to your profile. It stops before submitting so you can review everything first.
- **`/career-ops contacto`** — Finds a hiring manager or team member on LinkedIn and drafts a short outreach message for you to send.
- **`/career-ops deep`** — Researches the company and the role in depth. Use this when you are on the fence and want more information before deciding.
- **`/career-ops tracker`** — Shows the status of every role in your pipeline. Run this any time you want to see where things stand.
<Callout title="Tip">
  You do not have to go in order. If a role scores 4.8 but you have never heard of the company, run `/career-ops deep` first. The commands work on their own — use which ever one fits your situation.
</Callout>

## Configurare portals.yml
`portals.yml` è il file che stabilisce che cosa cerca lo scanner e dove lo cerca. Lo crei una sola volta a partire dal modello incluso, poi lo modifichi in base ai ruoli a cui punti.
Esegui questo comando dalla cartella del progetto:
```bash title="Terminal"
cp templates/portals.example.yml portals.yml
```
Apri `portals.yml` in un qualsiasi editor di testo. Il file ha tre sezioni. I passaggi qui sotto le spiegano una per una.
### Impostare il filtro sui titoli
Il filtro sui titoli è il criterio con cui lo scanner decide se vale la pena mostrarti un annuncio. Confronta il titolo della posizione con due elenchi di parole chiave.
Trova la sezione `title_filter` nella parte alta del file:
```yaml title="portals.yml"
title_filter:
  positive:
    - "AI"
    - "ML"
    - "Product Manager"
  negative:
    - "Junior"
    - "Intern"
  seniority_boost:
    - "Senior"
    - "Staff"
    - "Lead"
```
**Sostituisci l'elenco `positive`** con le parole chiave che corrispondono ai ruoli a cui punti. Per passare, un annuncio deve contenere almeno una parola chiave di questo elenco. Il controllo non distingue tra maiuscole e minuscole, quindi `"AI"` intercetta anche `"ai engineer"`.
**Sostituisci l'elenco `negative`** con le parole chiave che escludono un annuncio. Se una di queste compare nel titolo, l'annuncio viene scartato, anche se conteneva una parola chiave positiva.
**Lascia `seniority_boost` così com'è**, a meno che tu non voglia aggiungere o togliere livelli di seniority. Queste parole chiave non escludono nulla: si limitano a far salire nei risultati gli annunci che le contengono.
**Esempio:** se cerchi ruoli da sviluppatore Rails, il tuo filtro potrebbe essere questo:
```yaml title="portals.yml"
title_filter:
  positive:
    - "Rails"
    - "Ruby"
    - "Full Stack"
    - "Backend"
  negative:
    - "Junior"
    - "Intern"
    - "PHP"
    - "Java"
  seniority_boost:
    - "Senior"
    - "Staff"
    - "Lead"
```
<Callout title="Suggerimento">
  Parti con un elenco `positive` breve, da tre a cinque parole chiave. Puoi sempre aggiungerne altre in seguito. Con un elenco lungo diventa più difficile capire perché un annuncio è passato o è stato scartato.
</Callout>
### Aggiungere le aziende da monitorare
La sezione `tracked_companies` è l'elenco delle aziende specifiche che vuoi far controllare allo scanner a ogni esecuzione. Lo scanner va direttamente sulla pagina delle posizioni aperte di ciascuna azienda e legge i ruoli disponibili.
Trova la sezione `tracked_companies` nella parte bassa del file. Ogni voce ha questo aspetto:
```yaml title="portals.yml"
tracked_companies:
  - name: Anthropic
    careers_url: https://job-boards.greenhouse.io/anthropic
    api: https://boards-api.greenhouse.io/v1/boards/anthropic/jobs
    enabled: true
  - name: OpenAI
    careers_url: https://openai.com/careers
    enabled: true
```
**Per aggiungere un'azienda**, copia una voce esistente e cambia i valori:
<div className="rounded-lg bg-radial-[at_bottom] from-blue-500/20 p-4 border bg-origin-border border-fd-primary/10 prose-no-margin dark:bg-black/20">
  <div className="rounded-xl bg-fd-background p-3">
    | Campo         | Che cosa inserire                                                                                  |
    | ------------- | -------------------------------------------------------------------------------------------------- |
    | `name`        | Il nome dell'azienda, come vuoi che compaia nei risultati                                          |
    | `careers_url` | L'URL diretto della pagina con le posizioni aperte dell'azienda                                    |
    | `api`         | Facoltativo. L'URL dell'API di Greenhouse, se l'azienda usa Greenhouse. Se non sei sicuro, omettilo. |
    | `enabled`     | Imposta `true` per includere l'azienda o `false` per saltarla senza eliminare la voce.             |
  </div>
</div>
**Per trovare il `careers_url` di un'azienda**, vai sul suo sito, clicca su Careers, Jobs o «Lavora con noi» e copia l'URL della pagina che elenca le posizioni aperte. È quello l'URL da usare.
**Per disattivare un'azienda senza eliminarla**, imposta `enabled: false`:
```yaml title="portals.yml"
  - name: Stripe
    careers_url: https://stripe.com/jobs/search
    enabled: false
```
<Callout title="Nota">
  Ogni azienda in `tracked_companies` deve avere un `careers_url`. Senza, lo scanner non ha una pagina da visitare e salta quella voce.
</Callout>
### Controllare le query di ricerca
La sezione `search_queries` esegue ricerche web più ampie per trovare ruoli in aziende che non sono nel tuo elenco di quelle monitorate. Il modello include molte query già pronte.
Per iniziare non serve modificare questa sezione. Le query già pronte coprono i principali portali di lavoro, tra cui Greenhouse e Ashby.
Quando vorrai personalizzarle, ogni query ha questo aspetto:
```yaml title="portals.yml"
search_queries:
  - name: Greenhouse — Rails Engineer
    query: 'site:job-boards.greenhouse.io "Rails Engineer" OR "Ruby on Rails" remote'
    enabled: true
```
Per disattivare una query che non ti serve, imposta `enabled: false`. Per aggiungerne una nuova, copia una voce esistente, dalle un nuovo `name` e aggiorna il testo di `query`.
## Avviare una scansione
Ci sono due modi per avviare una scansione. Usa quello più adatto a ciò che ti serve.
### Opzione A — Eseguire direttamente lo script
```bash title="Terminal"
npm run scan
```
Esegui il comando dalla cartella del progetto. Lo script legge `portals.yml`, interroga direttamente l'API di ogni azienda e scrive i nuovi annunci in `data/pipeline.md`. Non consuma token AI e impiega circa 30 secondi.
Questa opzione funziona per tutte le aziende la cui pagina delle posizioni aperte gira su una piattaforma per cui lo scanner ha un provider integrato: Greenhouse, Ashby e Lever, più decine di altri sistemi ATS e portali di lavoro come Workable, Workday e SmartRecruiters. L'elenco completo è in [SUPPORTED_JOB_BOARDS.md](https://github.com/career-ops-hq/career-ops/blob/main/docs/SUPPORTED_JOB_BOARDS.md). Le aziende senza un provider corrispondente vengono saltate, e la scansione indica quante sono.
**Vedere i risultati in anteprima prima di salvarli:**
```bash title="Terminal"
npm run scan -- --dry-run
```
Esegue la scansione completa ma non scrive nulla su disco. Usalo per verificare le impostazioni dei filtri prima di salvare i risultati.
**Scansionare una sola azienda:**
```bash title="Terminal"
npm run scan -- --company Anthropic
```
Sostituisci `Anthropic` con il nome di una qualsiasi azienda del tuo elenco `tracked_companies`. La corrispondenza non distingue tra maiuscole e minuscole.
### Opzione B — Eseguire la scansione con l'AI dentro Claude Code
Apri Claude Code nella cartella del progetto e scrivi:
```bash title="Claude Code"
/career-ops scan
```
Questa versione visita direttamente la pagina delle posizioni aperte di ogni azienda usando un browser, quindi funziona anche con le aziende che non hanno un'API pubblica. Esegue inoltre le `search_queries` del tuo `portals.yml` per trovare ruoli in aziende che non sono nel tuo elenco di quelle monitorate.
Usa questa opzione quando:
- Un'azienda del tuo elenco usa una piattaforma per cui lo script non ha un provider, e quindi la scansione con lo script la salta
- Vuoi scoprire nuove aziende, non solo controllare quelle che conosci già
- La scansione con lo script non ha trovato qualcosa che ti aspettavi di vedere
<Callout title="Suggerimento">
  L'Opzione B consuma token dell'API di Claude e richiede più tempo dello script. Per un controllo quotidiano veloce, l'Opzione A è più rapida.
</Callout>

Ecco che cosa significa ogni riga:
<div className="rounded-lg bg-radial-[at_bottom] from-blue-500/20 p-4 border bg-origin-border border-fd-primary/10 prose-no-margin dark:bg-black/20">
  <div className="rounded-xl bg-fd-background p-3">

    |---|---|
    | **Companies scanned** | Quante aziende di `tracked_companies` sono state controllate |
    | **Total jobs found** | Tutte le posizioni aperte viste in quelle aziende, prima di qualsiasi filtro |
    | **Filtered by title** | Annunci rimossi perché il titolo non corrispondeva al tuo `title_filter` |
    | **Duplicates skipped** | Annunci già presenti nella tua pipeline o nel tracker, che non vengono aggiunti di nuovo |
    | **New offers added** | Annunci che hanno superato tutti i filtri e che per te sono nuovi |
  </div>

Se **New offers added** è 0, cerca prima di tutto questo avviso nel risultato della scansione:
```text title="Terminal"
⚠️  1 target(s) returned zero jobs without a successful HTTP response: Acme
```
Significa che il portale di quell'azienda non ha mai risposto correttamente, quindi lo zero non dimostra che non abbia posizioni aperte. L'azienda viene registrata come `unverified_zero` in `data/portal-health.tsv` e l'episodio si aggiunge alla sua serie di errori consecutivi. Controlla quel portale prima di cambiare i filtri.
Se l'avviso non c'è, il tuo filtro sui titoli potrebbe essere troppo restrittivo. Prova ad aggiungere una parola chiave all'elenco `positive` e avvia di nuovo la scansione.
**Dove finiscono i nuovi annunci:** ogni nuovo annuncio viene aggiunto come riga in `data/pipeline.md`. È l'elenco degli annunci in attesa di valutazione.
**A che cosa serve `data/scan-history.tsv`:** ogni URL che lo scanner vede, che sia stato aggiunto, filtrato o saltato, viene registrato qui. È così che lo scanner evita di mostrarti due volte lo stesso annuncio nelle scansioni successive. Fa eccezione un annuncio rimosso dall'impostazione `location_filter` o `max_posting_age_days` di `portals.yml`: viene registrato come `skipped_location` o `skipped_age` e può ricomparire quando cambi quell'impostazione. Non devi modificare questo file.

Quando `/career-ops pipeline` ha finito, ogni annuncio ha un punteggio da 1 a 5. Il report completo di ogni ruolo è nella cartella `reports/`. Il punteggio indica quanto il ruolo corrisponde al tuo profilo.
Usa il punteggio come punto di partenza:

    | **4,0 – 4,4**  | Buona corrispondenza. Esegui `/career-ops apply`. Puoi anche eseguire prima `/career-ops contacto` per contattare qualcuno del team prima di candidarti. |
    | **3,5 – 3,9**  | Può andare in un senso o nell'altro. Esegui `/career-ops deep` per saperne di più prima di decidere.                                            |

Ecco che cosa fa ogni comando:
- **`/career-ops apply`** — Apre il modulo di candidatura e scrive risposte su misura per il tuo profilo. Si ferma prima dell'invio, così puoi rivedere tutto.
- **`/career-ops contacto`** — Trova su LinkedIn un hiring manager o un membro del team e prepara la bozza di un breve messaggio di contatto che invierai tu.
- **`/career-ops deep`** — Fa una ricerca approfondita sull'azienda e sul ruolo. Usalo quando sei indeciso e vuoi più informazioni prima di scegliere.
- **`/career-ops tracker`** — Mostra lo stato di ogni ruolo nella tua pipeline. Eseguilo ogni volta che vuoi vedere a che punto sei.
<Callout title="Suggerimento">
  Non devi seguire un ordine. Se un ruolo ottiene 4,8 ma non hai mai sentito nominare l'azienda, esegui prima `/career-ops deep`. I comandi funzionano in modo indipendente: usa quello più adatto alla tua situazione.

## Install the Playwright package
Run `npm install` from the career-ops root folder:
```bash title="Terminal"
npm install
```
This installs Playwright and all other project dependencies declared in `package.json`. Skip this step if you already ran it during initial setup.
## Download Chromium
Playwright needs its own copy of Chromium to automate. The installer normally downloads it automatically right after dependencies; if `npm run doctor` reports it missing, download it by running:
```bash title="Terminal"
npx playwright install chromium
```
This is a one-time step. You do not need to repeat it after `npm` updates.
## Configure the Playwright MCP
The Playwright MCP lets Claude control the browser directly during the `/career-ops apply` step — navigating to job application forms, reading field labels, and suggesting answers.
### Register the MCP server
Run this command from the career-ops root folder to register the Playwright MCP with Claude Code:
```bash title="Terminal"
claude mcp add --scope project playwright -- npx @playwright/mcp@latest
```
This is the one-step registration method from the [Playwright MCP docs](https://playwright.dev/docs/getting-started-mcp), with `--scope project` added so Claude Code writes the server entry to `.mcp.json` in the career-ops root, one of the files `npm run doctor` checks. The next time you start Claude Code there, approve the server when it asks.
To use it in every project instead, run the command with `--scope user`. `npm run doctor` does not read user-scoped servers, so it will then warn that it cannot detect the MCP even though Claude Code loads it.
### Manual configuration (alternative)
If you prefer to configure it by hand, add the following entry to `.mcp.json` in the career-ops root (create the file if it does not exist):
```json title=".mcp.json"
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    }
  }
}
```
Restart Claude Code after saving the file and approve the server when it asks. career-ops will then have access to `browser_navigate` and `browser_snapshot` during apply sessions.

```bash title="Terminal"
npm run doctor
```
Look for confirmation that Playwright, Chromium, and the MCP server are all ready. If the check passes, setup is complete.
